# Обзор фронтенд-слоя вебвью AI Office

Документ описывает клиентскую часть дашборда: файлы `media/office.html`, `media/office.js`, `media/office.css`, `media/icons.js`, `media/avatars.js`, а также взаимодействие вебвью с хостом расширения (`src/webview/provider.ts`).

Актуализировано 2026-08-02: учтены правки фронтенд-слоя, реализовавшие все четыре «точки роста» из первой версии обзора (см. §6).

## 1. Структура вебвью

Дашборд — это статическая HTML-страница `media/office.html` без фреймворков и сборки: чистый DOM + один большой скрипт. Расширение читает файл как шаблон и подставляет плейсхолдеры `{{…}}` в `OfficeDashboardProvider.getHtml()` (`src/webview/provider.ts:222`):

- `{{cssUri}}`, `{{jsUri}}`, `{{iconsUri}}`, `{{avatarsUri}}` — URI ресурсов через `webview.asWebviewUri` (корень ограничен `localResourceRoots` на каталог `media/`);
- `{{cspSource}}` и `{{nonce}}` — CSP с `default-src 'none'`, скрипты только по nonce, стили с `'unsafe-inline'` (нужен для inline-стилей и `innerHTML` с SVG);
- `{{lang}}` — локаль VSCode (`uiLocale()`), проставляется в `<html lang="…">` и служит источником языка UI для `office.js`;
- `{{version}}` — версия расширения в подвале.

Скелет страницы статичный, наполнение — динамическое. Сверху вниз (см. `media/office.html`):

1. `.office-header` — логотип, заголовок, бейдж модели (`#office-model`), переключатель idle (`#idle-toggle`), статус (`#office-status` с точкой и `#status-text`).
2. `#stop-btn` — кнопка экстренной остановки на всю ширину.
3. `#stop-banner` — красный баннер «остановка активна» с кнопкой Resume (скрыт по умолчанию).
4. `#waiting-banner` — баннер главной модели: «ждёт вас» / «работает» / «завершила ход».
5. `#floor` — сетка комнат офиса. В разметке только плейсхолдер `#floor-empty`; комнаты целиком строятся скриптом.
6. `.stats-bar` — пять счётчиков: working / done / errors / total / completed.
7. `.timeline-section` — `<canvas id="timeline">` и селектор окна времени.
8. `#usage-panel` — лимиты плана: динамические группы `#usage-subscription` (Claude), `#usage-kimi` (Kimi), строка прогноза `#usage-forecast` и статичная группа `#usage-cost` с тремя барами (block / weekly / weekly-opus).
9. `#event-log` — журнал активности (последние 50 записей).
10. `#agent-drawer` — нижняя выдвижная панель с деталями агента (fixed, скрыта по умолчанию).

Скрипты подключаются в конце body в порядке: `icons.js` → `avatars.js` → `office.js`. Первые два не содержат логики — они лишь записывают глобальные реестры SVG-строк: `window.__ROOM_ICONS` (иконки комнат 14×14, включая `_custom` — «дверь» для произвольных комнат) и `window.__AGENT_AVATARS` + `window.__AGENT_AVATAR_MAP` (аватары по ролям и карта «имя агента → ключ аватара», покрывающая предопределённых специалистов проекта — backend, security, devops, интеграции 1С/Telegram и т.д.).

Локализация: `office.js` читает `lang` из `<html>`, выбирает словарь `MESSAGES` (en/ru) и заполняет элементы с атрибутом `data-i18n` через `localizeDom()`. Для количественных строк есть `trCount()` с корректными русскими плюралами (1/2–4/5+). Статическая часть разметки переведена через `data-i18n`, динамическая — через `tr()` в момент рендера.

## 2. Рендер карты офиса и фигурок агентов (`media/office.js`)

### Комнаты

Комнаты не зашиты в HTML. Реестр `ROOM_META` (`office.js:43`) задаёт цвет и локализованную подпись для десяти известных id (`directors`, `backend`, `frontend`, `qa`, `security`, `devops`, `integrations`, `ai-lab`, `iot`, `lobby`). Любой другой id (например, кастомная комната из конфига проекта) получает цвет из палитры `CUSTOM_ROOM_PALETTE` по хэшу имени (`roomColor`, `office.js:60`), подпись генерируется из id («ml-pipeline» → «Ml Pipeline»), иконка — общая `_custom`. Порядок вывода определяет `sortRooms()`: известные комнаты по `ROOM_ORDER`, кастомные после них по алфавиту, `lobby` всегда последней (рендерится на всю ширину, `.room--lobby`).

`ensureRooms(roomIds)` (`office.js:274`) синхронизирует DOM с набором комнат, занятыми текущими агентами. Оптимизация: подпись упорядоченного списка id хранится в `data-rooms` на `#floor`; если она не изменилась — rebuild пропускается. Иначе старые `.room` удаляются и строятся заново: div с `data-room`, инлайновой CSS-переменной `--room-accent`, шапкой (SVG-иконка + подпись) и контейнером `.agents`. Акцентный цвет комнаты попадает в CSS именно через `--room-accent` — это единственное место, где JS управляет цветом.

### Цикл рендера

Единственный вход рендера — `render()` (`office.js:401`), вызываемый на каждое сообщение `full_state` от хоста. Подход «перерисовать всё»: `.agents` каждой комнаты очищается через `innerHTML = ""`, затем фигурки создаются заново по `currentAgents`. При этом пересборка DOM защищена подписью: `renderSignature()` (`office.js:388`) сериализует в JSON всё, что `render()` рисует (флаг `hideIdle`, `completedCount`, флаг ожидания и по каждому агенту — имя, состояние, комнату, задачу, `activeCount`, `lastActivity`), и при совпадении с `lastRenderSignature` рендер выходит без единого изменения DOM. Поскольку `full_state` приходит на каждое hook-событие, а фигурки меняются редко, это устраняет мерцание (сброс hover и перезапуск `agentAppear`), которое давала безусловная перерисовка. Ничего не теряется: журнал и таймлайн строятся диффом в обработчике сообщения **до** вызова `render()` и от пропуска не зависят; интервальные обновления (таймлайн, баннер, отсчёты лимитов) идут мимо подписи и не затронуты.

По каждому агенту (кроме `Main agent`, который живёт в верхнем баннере, а не в комнате):

- Состояние — CSS-класс `agent--working|done|error|idle`.
- Фигурка — pill-бейдж, собираемый через `createElement` (`office.js:448-489`): SVG-аватар (`getAgentIcon` смотрит сначала в `__AGENT_AVATAR_MAP` по имени агента, фолбэк — иконка комнаты), сокращённое имя (`shortName` срезает суффиксы `-specialist`/`-lead`, префикс `module-`), при `activeCount > 1` бейдж «×N» (параллельные инстансы одного типа), и абсолютно позиционированный тултип с именем, задачей и временем последней активности. Всё, что приходит от хоста (имя, `agent.task`, время), вставляется через `textContent` — то же правило, что в drawer; `innerHTML` остался только для аватара, а он берётся из собственного доверенного локального реестра `icons.js`/`avatars.js`. Тултип сохранён на прежних CSS-классах, так что стрелка-псевдоэлемент и hover-правило работают без изменений в CSS.
- Клик открывает drawer (`toggleAgentDrawer`), имя захватывается через IIFE (в файле ES5-стиль с `var`).
- Idle-агенты при `hideIdle` (по умолчанию включено) не рендерятся по одному: на комнату создаётся один чип «+N» с тултипом-перечнем имён. Это компакт-режим против раздувания высоты панели.

Комната, где есть работающий агент, получает класс `room--active` — подсветка левой кромки цветом `--room-accent` и оживление иконки/подписи.

Тем же проходом `render()` обновляет счётчики stats-bar, статус-точку в шапке (off / on / wait, с приоритетом: waiting → субагенты работают → главная модель работает → idle → offline), баннер главной модели (`renderMainBanner`) и таймлайн (`renderTimeline`).

### Таймлайн

`renderTimeline()` (`office.js:591`) рисует на `<canvas>` полосу активности: по массиву `timelineEvents` (пары `agent_start`/`agent_stop` из журнала) строятся закрашенные пролёты цвета комнаты агента, незавершённые — до «сейчас» с бо́льшей непрозрачностью. Учитывается `devicePixelRatio` (canvas масштабируется), под полосой — адаптивная временная сетка (шаг 1/3/5/15 минут или 1 час в зависимости от окна). Окно выбирается селектором `#timeline-window` (5 мин – 6 ч). Таймлайн и баннер перерисовываются по `setInterval` каждые 2 с, панель лимитов — каждые 30 с (обновление отсчётов «сброс через …»).

## 3. Состояние и localStorage

### Состояние в памяти

Вебвью не хранит историю между перезапусками (кроме трёх ключей ниже): всё «горячее» состояние — набор модульных переменных в глобальной области `office.js`:

- `currentAgents` — карта «имя → { state, room, task, activeCount, lastActivity }», целиком заменяется на каждое `full_state`;
- `timelineEvents`, `eventCount`, `completedCount`, `agentRoomCache` — журнал и агрегаты, накапливаются с момента загрузки вебвью;
- `lastUsage`, `currentWaiting`, `stopActive`, `mainWorkingSince` — снимки лимитов, ожидания пользователя, флага экстренной остановки и момента старта хода главной модели;
- `drawerAgent` / `drawerRoom` / `drawerDetail` — состояние выдвижной панели;
- `lastRenderSignature` — JSON-подпись последнего отрисованного состояния (см. §2).

Журнал событий (`addLogEntry`, `office.js:672`) строится не из отдельных push-событий, а **диффом соседних `full_state`**: появление агента в `working` → `agent_start`, переход в `done`/`error` → `agent_stop`. Из тех же записей кормится таймлайн. Счётчик `completed` не считает ходы главной модели — только субагентов.

### localStorage

Всего три ключа, все с префиксом `aiOffice.`:

| Ключ | Содержимое | Где используется |
|---|---|---|
| `aiOffice.timelineWindowMs` | окно таймлайна в мс (строка-число) | `initTimelineSelector` (`office.js:966`) |
| `aiOffice.hideIdleAgents` | `"1"`/`"0"` — сворачивать idle-агентов в чипы | `initIdleToggle` (`office.js:358`) |
| `aiOffice.usageHistory` | JSON: `kind → [{t, pct}]` — скользящее окно (90 мин, макс. 500 семплов) утилизации лимитов для прогноза burn-rate | `recordUsageSamples` / `forecastLimit` (`office.js:1086`, `1110`) |

Два нюанса:

- **Миграция ключей после ребрендинга.** Все чтения идут через `readStorageKey(newKey, oldKey)` (`office.js:22`), которая при пустом новом ключе одноразово переносит значение со старого `claudeOffice.*` и удаляет его. Так переживают обновление настройки пользователя и накопленная история лимитов.
- **Защита от недоступного хранилища.** Каждый доступ обёрнут в `try/catch` (в webview localStorage может быть отключён политикой) — в худшем случае настройки просто не сохраняются.

История лимитов ограничена двумя независимыми способами: семплы старше 90 минут отбрасываются, а поверх этого действует жёсткий кэп `USAGE_HISTORY_MAX_SAMPLES = 500` на массив одного вида лимита (`office.js:1079`, `1101`) — 90-минутное окно само по себе не ограничивает длину при патологически частых апдейтах. Дополнительно резкое падение утилизации (> 5 п.п.) трактуется как сброс окна лимита — старый тренд обнуляется. Прогноз считается, только если окно наблюдений ≥ 10 минут и темп положительный; показывается самый «горящий» лимит из обоих провайдеров, если он наступит раньше сброса окна (`renderForecast`, `office.js:1121`).

### Классы ошибок и таймеры

Ошибки провайдеров лимитов (`usage_error`) не затирают живые данные других источников — показ ошибки в шапке панели происходит, только если соответствующая секция пуста (`renderUsageError`, `office.js:1213`). Два интервала внизу файла (`office.js:1233-1234`) поддерживают «живость» без участия хоста: 2 с — таймлайн и длительность хода в баннере, 30 с — отсчёты до сброса лимитов.

## 4. Стилистика `media/office.css`

### Подход

Один файл (~970 строк после зачистки, CRLF), без препроцессоров и внешних зависимостей. Именование — упрощённый БЭМ: блок `.agent`, модификаторы состояния `.agent--working`, `.room--active`, элементы `.usage-bar-fill`. Состояние всегда выражается классом-модификатором, а не инлайн-стилем, — JS меняет только классы и текст (единственные исключения: `--room-accent` и ширина `.usage-bar-fill`).

### Тема

Палитра двухслойная:

- семантические переменные привязаны к теме VSCode через `var(--vscode-…, fallback)`: `--vscode-sideBar-background`, `--vscode-panel-border`, `--vscode-foreground`, `--vscode-descriptionForeground`, `--vscode-editorHoverWidget-*`, шрифты `--vscode-font-family` / `--vscode-editor-font-family`. Фолбэки — тёмная тема VSCode (#1e1e1e и др.), так что панель встроена в любую пользовательскую тему, но в отрыве от хоста тоже выглядит нормально;
- поверх — фиксированный набор акцентов (`--blue`, `--green`, `--red`, `--yellow`, `--purple`, …) в парах «яркий / приглушённый» (`--blue` + `--blue-dim`): яркий — рамки, иконки, текст; приглушённый — фон бейджа. Цвета состояний агента консистентны во всех модулях: working = синий, done = зелёный, error = красный, waiting = жёлтый.

Акцент комнаты — инлайновая `--room-accent` от JS; CSS лишь потребляет её (левая кромка `.room`, свечение `.room--active`, цвет иконки). Дефолт `--teal` задан в CSS на случай отсутствия инлайна.

### Раскладка и адаптивность

- Этаж — CSS Grid `.floor` в 3 колонки, на ширине ≤ 360px — 2, ≤ 240px — 1 (медиазапросы под узкую боковую панель); лобби всегда `grid-column: 1 / -1`.
- Фигурки внутри комнаты — flex-wrap, тултип абсолютный над бейджем со стрелкой-псевдоэлементом.
- Usage-бары — grid `80px 1fr auto` (подпись / трек / значение), drawer-история — grid `62px 64px 1fr`.
- Числа с `font-variant-numeric: tabular-nums`, чтобы счётчики не дёргались.
- Drawer — `position: fixed` снизу, `max-height: 65vh`, собственный скролл, тонкие кастомные скроллбары (3px) у лога и drawer.

### Анимации

Небольшой набор keyframes с чёткими ролями: `agentAppear` (появление фигурки/баннера), `pulse`/`statusPulse` (работа, ожидание), `shake` + `blink` (ошибка — сначала тряска, затем мигание с задержкой 0.4s), `handWave` (жест ✋ в баннере ожидания), `logSlide` (новые записи журнала и истории), `drawerIn`, `tooltipIn`. Правило `[hidden] { display: none !important }` в шапке файла защищает скрытие от авторских `display: flex` — комментарий рядом объясняет зачем (UA-стиль `[hidden]` проигрывает любому author display).

### Замечания

- Осиротевшие стили селектора сессий (`.session-selector`, `.session-btn`, `.session-dot`, `.agent-session-dot`, ~60 строк без соответствующей разметки) удалены из файла при актуализации — мёртвого кода в таблице стилей больше нет.
- Часть значений захардкожена вне переменных (#555, #93c5fd, rgba-подложки) — при полной поддержке светлых тем это потенциальные тёмные пятна, хотя основная палитра темонезависима.

## 5. Взаимодействие с хостом расширения

Канал — стандартный `acquireVsCodeApi()` (`office.js:3`) против `OfficeDashboardProvider` (`src/webview/provider.ts`). Провайдер обслуживает **два слота одновременно**: вид в боковой панели (`aiOffice.dashboard`, `resolveWebviewView`) и редакторская вкладка (`aiOffice.dashboardEditor`, `openInEditor`). Каждый слот — `{ webview, ready }`; рассылка (`broadcast`) идёт только в слоты с `ready === true`.

### Протокол: хост → вебвью

| Сообщение | Когда шлёт хост | Обработка в `office.js` |
|---|---|---|
| `full_state { agents, model, waiting }` | любое изменение состояния агентов; повторно при replay | дифф с предыдущим состоянием → журнал/таймлайн, замена `currentAgents`, обновление модели и ожидания, `render()` (пропускается, если подпись не изменилась) |
| `usage_update { data: { subscription: { claude, kimi }, cost } }` | апдейт лимитов/расходов любого провайдера | семплы в `usageHistory`, `renderUsage()` |
| `usage_error { source, message }` | ошибка опроса провайдера | `renderUsageError` (не затирает живые данные) |
| `stop_state { active, since }` | переключение экстренной остановки; replay | флаг + запись в журнал, `renderStop()` |
| `agent_detail { detail }` | ответ на запрос drawer и дальнейшие пуши, пока drawer открыт | обновление `drawerDetail`, если имя совпадает, `renderAgentDrawer()` |

Обработчик — один `window.addEventListener("message", …)` (`office.js:922`) с ветвлением по `msg.type`.

### Протокол: вебвью → хост

| Сообщение | Откуда | Реакция хоста |
|---|---|---|
| `webview_ready` | после инициализации и на каждый `visibilitychange` (становление видимым) | `slot.ready = true`, `replay()` кэшированного состояния, колбэк `onReady` |
| `toggle_stop` | кнопки `#stop-btn` и `#stop-resume` | `onToggleStop` (переключение stop-флага, зеркалируемого в `~/.claude/office-stop.json`) |
| `agent_detail_request { name }` | открытие drawer по клику на фигурку | `onAgentDetailRequest(name)` |
| `agent_detail_close` | закрытие drawer (кнопка, Esc, повторный клик) | `onAgentDetailClose` |

### Жизненный цикл и защита от устаревшего UI

Ключевая проблема webview — сообщения, потерянные, пока панель скрыта (даже с `retainContextWhenHidden` вид может дропать события). Решение двустороннее и симметричное:

- **со стороны вебвью**: на `visibilitychange` → повторный `webview_ready` (`office.js:1230`);
- **со стороны хоста**: провайдер кэширует последний `full_state`, `stop_state`, `usage_update` и все `usage_error` в полях `lastState`/`lastStop`/`lastSubscription`/`lastCost`/`usageErrors` и при `ready` или возврате видимости (`onDidChangeVisibility` / `onDidChangeViewState`) прогоняет `replay()` — полную повторную посылку кэша (`provider.ts:193`).

То есть вебвью можно пересоздать в любой момент — оно восстановится из replay, а не из своей памяти. Это согласуется с тем, что персистентных (кроме трёх ключей localStorage) данных на клиенте нет.

### Безопасность канала

- CSP: `default-src 'none'`, скрипты по 32-символьному nonce, ресурсы — только из `media/` (`localResourceRoots`).
- Данные из хоста (имена агентов, тексты задач, время активности) везде идут через `textContent` — и в drawer, и в фигурке с тултипом; `innerHTML` используется только для SVG-иконок из собственного доверенного набора (`icons.js`/`avatars.js`).
- Хост валидирует входящее минимально, но по делу: у `agent_detail_request` проверяется непустая строка `name` (`provider.ts:178`).

## 6. Итоговые наблюдения

Сильные стороны слоя: нулевые зависимости и сборка, полная интеграция с темой VSCode, продуманный replay-протокол против потери сообщений, аккуратная локализация с плюралами, самовосстанавливающийся UI после скрытия/пересоздания панели, осторожная работа с localStorage и самоочистка истории лимитов.

### Реализованные улучшения (2026-08-02)

Все четыре «точки роста» из первой версии обзора закрыты:

1. **Безопасная сборка фигурки.** Тултип и весь бейдж агента пересобраны на `createElement` + `textContent` для данных хоста (`office.js:448-489`); `innerHTML` остался только для доверенного локального SVG-аватара. Инъекционная точка устранена, CSS-классы тултипа сохранены.
2. **Зачистка CSS.** Осиротевшие стили селектора сессий (`.session-selector`, `.session-btn`, `.session-dot`, `.agent-session-dot`) удалены из `office.css`.
3. **Рендер по подписи.** `render()` пропускает пересборку фигурок при неизменной JSON-подписи состояния (`renderSignature`/`lastRenderSignature`, `office.js:386-404`) — мерцание и сброс hover на каждое hook-событие устранены; журнал/таймлайн по-прежнему строятся из каждого `full_state`, интервальные обновления не затронуты.
4. **Кэп истории лимитов.** Добавлен `USAGE_HISTORY_MAX_SAMPLES = 500` на массив семплов одного вида лимита поверх 90-минутного окна (`office.js:1079`, `1101`).

### Оставшиеся наблюдения

Существенных открытых проблем во фронтенд-слое не осталось. Мелочи на будущее:

- Часть цветов в `office.css` захардкожена вне переменных (#555, #93c5fd, rgba-подложки) — заметно только при полной поддержке светлых тем.
- Подпись рендера сериализует всех агентов на каждый `full_state` (O(n) по ростру в JSON) — дёшево при десятках агентов, но при сотнях можно заменить на инкрементальный хэш; практической необходимости сейчас нет.
