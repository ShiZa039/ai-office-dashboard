# Bug — агенты перестают отображаться при открытии второго окна VS Code

**Дата:** 2026-04-17
**Версия:** `claude-office-dashboard-0.7.0.vsix` (требует подтверждения на более ранних)
**Платформа:** Windows 11 Pro 10.0.26200, VS Code
**Приоритет:** высокий — расширение бесполезно для любого user, работающего с 2+ окнами одновременно
**Статус:** ✅ диагностировано + исправлено (см. блок «Разбор и фикс» ниже).

---

## Разбор и фикс (2026-06-03)

Гипотезы из репорта (коллизия watcher'ов / кросс-окно override / singleton) **кодом не подтвердились**: каждое окно VSCode — отдельный extension host, у каждого свои `EventWatcher`, `AgentStateStore` и конфигурация. Общего изменяемого состояния (порта/лок-файла) между окнами нет. Чтение общего jsonl идёт независимо, каждое окно со своим offset.

**Настоящая корневая причина (версии до 0.7.0):** хук шлёт `session_stop` на **каждый ход** главного агента (это `Stop`-хук — видно в `~/.claude/agent-events.jsonl`: десятки `session_stop` за сессию). Обработчик `session_stop` сбрасывает всех агентов в idle. До 0.7.0 фильтра по `cwd` не было → стор глобальный → `session_stop` из второго окна постоянно обнулял агентов первого. Открыл второе окно → дашборд первого мигает в пустоту.

**Фикс уже в 0.7.0:** добавлен `cwd`-фильтр — события чужого окна отсекаются ([src/agentState.ts](src/agentState.ts), `matchesCwd`). Если баг наблюдался на 0.7.0 — значит установлена была более ранняя сборка, либо это multi-root edge-case (ниже).

**Дофикс в 0.8.0:** `cwd`-фильтр теперь матчит по **всем** workspace-папкам окна, а не только по `workspaceFolders[0]`. Это чинит multi-root `.code-workspace` (как Signe_server), где Claude запускался из папки, не равной первому руту, и события отсекались. Также добавлен `onDidChangeWorkspaceFolders` для пересборки фильтра на лету.

## Симптом

Claude Office Dashboard корректно показывает активных агентов (секция с workers / timeline / activity log) **только когда открыто ровно одно окно VS Code**.

Как только открывается **второе** окно VS Code (неважно: соседний проект, `File → New Window`, открытие репо в отдельном окне через `code .`) — дашборд **перестаёт отображать агентов**. Секция опустевает, новые spawn-события агентов не появляются.

Наблюдение не привязано к тому, в каком из окон открыт сам Claude Office — эффект тот же.

## Шаги воспроизведения

1. Открыть VS Code, расширение Claude Office установлено и активно.
2. Открыть проект (например, `d:/Code projects/BAZA_CRM/`) и вызвать `View → Claude Office`.
3. Запустить Claude-сессию в этом окне, инициировать задачу с субагентом (`Agent(...)` вызов).
4. **Ожидаемо:** в дашборде видно spawned агента, прогресс, лог.
5. Открыть второе окно VS Code: `File → New Window` → в нём открыть любой другой проект (например, `d:/Code projects/Signe_server/`).
6. Вернуться на окно #1, где Claude-сессия ещё идёт.
7. **Фактически:** секция активных агентов в Claude Office пустая или не обновляется, хотя Claude-сессия в окне #1 продолжает spawn'ить задачи.

## Ожидаемое поведение

- Каждое окно VS Code с установленным Claude Office должно независимо показывать агентов своей сессии/корневой папки.
- Либо: один экземпляр дашборда агрегирует агентов всех активных окон (с фильтром по `cwd`, как уже используется для usage).

## Гипотеза (без глубокого разбора кода)

Судя по логу из `BUG_REPORT_usage_spawn_einval.md` (`Claude Office: cwd filter = d:\Code projects\Signe_server`, `watching C:\Users\s_rpk\.claude\agent-events.jsonl`), расширение читает единый глобальный jsonl-файл событий агентов в `~/.claude/agent-events.jsonl`. При двух окнах возможные проблемы:

1. **Коллизия watcher'ов** — оба окна пытаются читать / tailить один и тот же файл, один инстанс блокирует обновления другого, либо отключает watcher при конкуренции.
2. **Кросс-окно cwd-фильтр** — второе окно переопределяет `cwd filter` на свой путь, и дашборд в первом окне начинает фильтровать по не-своему `cwd`, отсекая собственные события.
3. **Singleton-процесс / FileSystemWatcher API** — VS Code `workspace.createFileSystemWatcher` может иметь нюансы при мультиинстансе (каждое окно — отдельный extension host).

## Где смотреть

- `src/agentWatcher.ts` (или аналогичный файл наблюдения за `~/.claude/agent-events.jsonl`) — логика чтения jsonl, fs.watch/FSWatcher, фильтр по `cwd`.
- `src/extension.ts` → метод `activate` — как определяется "активное окно" и какой `cwd` попадает в фильтр.
- Выход в логах: воспроизвести и сверить `cwd filter = ...` в обоих окнах — совпадает или переопределяется.

## Минимальный workaround для user

Закрывать все лишние окна VS Code перед работой с дашбордом. Неприемлемо для рабочего потока (параллельные проекты — норма).
