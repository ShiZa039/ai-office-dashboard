# ADR-0001. Триаж prestart-litany для AI Office Dashboard

- **Статус:** принят
- **Дата:** 2026-08-03
- **Ссылки:** `prestart-litany.md` (read-only мастер-копия), `HOOKS-DESIGN.md`, `AGENTS.md`

## Контекст

В корень проекта добавлена `prestart-litany.md` — мастер-литания правил и
каталога грабель (52 инцидента), собранных на других проектах (ERP, SaaS,
IoT). Литания требует: определить профиль проекта, провести триаж каждого
пункта (IN / DEFERRED с условием активации / OUT) одним ADR, зафиксировать
компромиссы. Дополнительное требование проекта: всё перенесённое должно быть
**моделенезависимым** — работать одинаково для Claude Code, Kimi Code и
будущих агентов (см. `AGENTS.md`, направление «мультимодельность»).

## Альтернативы

1. **Принять литанию целиком** — отвергнуто: треть правил привязана к
   Docker/железу/прод-эксплуатации, которых у расширения VS Code нет.
2. **Не принимать ничего** — отвергнуто: часть грабель уже сработала бы
   (Windows/CRLF, рассинхрон двух конфигураций агента, протухание доков);
   часть правил у нас реализована стихийно и не зафиксирована.
3. **Триаж по профилю M** (выбрано) — взять ядро + профильные добавки M,
   остальное отсечь явно с причиной.

## Решение

### Профиль проекта: M — продукт без своего прода

Признаки: код, тесты, релизы (.vsix), нет своего сервера/БД/денег/железа.
По литании применимо: минимальное ядро 0.2 целиком, разделы II–IV, V.9
(публичный релиз), I.14 (персистентное состояние), профильные грабли.

### Статусы

- **IN** — принимаем (новое или формализация существующего).
- **ЕСТЬ** — уже реализовано в проекте; фиксируем, чтобы не потерять.
- **DEFERRED** — не делаем сейчас, условие активации записано.
- **OUT** — неприменимо к профилю M, причина указана.

### Ядро 0.2 (минимум, действует всегда)

| Пункт | Статус | Комментарий |

### Грабли (раздел VI)

**IN — переносим в живой каталог `docs/gotchas.md`** (со слагами, источник
инцидента — мастер-литания; новые проектные грабли добавляются туда же и
мигрируют в мастер-литанию):

- Версии и контракты: `gotcha-version-sot`, `gotcha-version-symmetry`,
  `gotcha-lexicographic-semver`, `gotcha-feature-test-debt`,
  `gotcha-tsc-no-b` (проект TS; references не используются, но принцип
  «знай слепые зоны своего tsc» — IN).
- Windows и кодировки: `gotcha-gitattributes` (**действие: создать
  `.gitattributes`** — файла нет, проект на Windows, sh/py/js едут в
  Linux-CI), `gotcha-non-ascii-toolchain` (уже куснуло: BOM/UTF-8 в хуках),
  `gotcha-case-insensitive-headers` (принцип регистронезависимой ФС —
  актуально для `normPath`), `gotcha-windows-bindmount` — OUT (нет Docker),
  но `gotcha-exec-bit` — IN (sh-скрипты в `hooks/`).
- Данные и логика: `gotcha-placeholder-data`, `gotcha-green-modules-dead-system`
  (закрывается II.7), `gotcha-orphan-config`, `gotcha-gitignored-dependency`.
- Процесс: `gotcha-docs-drift`, `gotcha-god-files`, `gotcha-phantom-tails`,
  `gotcha-silent-later`, `gotcha-ci-wrong-branch`, `gotcha-hook-shell-blind`
  (Git Bash vs PowerShell vs cmd на машинах пользователей),
  `gotcha-renumbered-parent` (ссылки только слагами — правило проекта),
  `gotcha-two-agent-configs` (закрыта IV.6 + паритет-тестами py/js),
  `gotcha-automated-prompt` (уже реализована: `is_automated_prompt` — ЕСТЬ),
  `gotcha-llm-stale-configs`.

**OUT — неприменимы к профилю M:**

- Все `[Docker]` (1–14, кроме `gotcha-exec-bit`), `[железо]/ESP32`,
  инфраструктура/прод (32–40), очереди (`gotcha-stale-workers`,
  `gotcha-silent-unregistered` — принцип перенесён в II.7,
  `gotcha-interval-schedule`), React-специфика (`gotcha-number-null`,
  `gotcha-modal-drag-close`, `gotcha-404-swallows-detail`).

### Моделенезависимость — три приёма (обязательны для всего перенесённого)

1. **`AGENTS.md` — единственная точка входа правил**; читается обоими CLI.
   Никаких дублей правил в файлах конкретного агента.
2. **Машинные гейты — только в хук-скриптах** `emit-agent-event.{py,js}`:
   они общие для обоих CLI, гейт добавляется один раз и работает везде;
   паритет py/js страхуется парой тестов `emitAgentEvent(.Py).test.ts`.
3. **Форматы хранения — plain markdown в репо** (ADR, грабли, Module Map),
   без привязки к skills/memory конкретного CLI; ритуалы — триггер-фразами
   в `AGENTS.md`.

## Причины

- Профиль M отсекает ~40% литании без потерь: у расширения нет прода, БД,
  контейнеров и железа.
- Дороже всего обходятся молчаливые расхождения (двух конфигураций агента,
  доков с кодом, схемы с парсером) — именно они закрываются IN-пунктами.
- Часть правил уже работает в проекте стихийно (ЕСТЬ); без фиксации они
  размываются при следующем рефакторинге.

## Компромиссы

- **≤40 строк на функцию — ориентир, не гейт.** Машинной проверки нет;
  следим глазами на ревью. Цена: постепенный рост `media/office.js` —
  смягчается Module Map (III.1).
- **Опасные команды без машинного гейта** (DEFERRED II.2). Цена: защита
  только дисциплиной; смягчается ask-гейтом самих CLI.
- **JSONL без retention.** Цена: файл растёт; смягчается ручным
  `aiOffice.clearEvents` и записанным условием активации (I.16).
- **`.gitattributes` добавляется точечно** (sh/py/js — LF), без
  перенормализации всего репозитория. Цена: теоретический CRLF-дрейф в
  прочих файлах, практически не наблюдавшийся.
- **ADR и доки — на русском**, идентификаторы и слаги не переводятся.
- **Триаж пересматривается** только при смене профиля (например, появился
  серверный компонент → профиль XL, пересмотр OUT-пунктов раздела V).

## Действия по внедрению (вне этого ADR)

1. Создать `.gitattributes` (`gotcha-gitattributes`).
2. Дополнить `AGENTS.md`: Module Map, ритуал закрытия, протокол отладки,
   правила из ядра 0.2 — одним блоком.
3. Создать `docs/gotchas.md` с IN-граблями.
4. Добавить wiring-тест «`event_type` скриптов ⊆ регистрации обоих CLI» (II.7).
5. Убрать старые .vsix из корня (III.6).
